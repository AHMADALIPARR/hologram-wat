## What is this?

hologram-ai is a Rust workspace that downloads Hugging Face models, compiles them into content-addressed `.holo` archives, and runs inference natively and in WebAssembly. ~50,000 lines of Rust. Cargo. Toolchains. Build steps.

**I ported the whole thing to WebAssembly Text.**

Not by compiling Rust to WASM. By *rebuilding* it — function by function, crate by crate — as an XML DAG that transforms via XSLT into pure WAT. Every instruction is visible. Every operation is auditable. Every byte is deterministic.

**Run it in any browser. Run it in any WASM runtime. Run it in a Hugging Face Space. No toolchain. No build. No trust required.**

## The Pipeline

```
    XML DAG DSL          XSLT                Pure WAT              WASM
  ┌─────────────┐   ┌──────────────┐   ┌──────────────┐   ┌────────────┐
  │  Human-      │   │  Deterministic│   │  Readable    │   │  Runs in   │
  │  readable    │──▶│  transform    │──▶│  WebAssembly │──▶│  any       │
  │  DAG         │   │  (pure func)  │   │  Text        │   │  browser   │
  └─────────────┘   └──────────────┘   └──────────────┘   └────────────┘
       SOURCE            TRANSFORM           GENERATED           EXECUTABLE
```

**XML is the source of truth.** WAT is generated, never hand-written.
**XSLT is the only path.** Same XML in → same WAT out, byte for byte.
**WAT is the proof.** Every instruction traces to a DAG node.

## Why?

### Because AI infrastructure should not require trust.

When you download a model, you trust the code that loads it. When you run inference, you trust the runtime. When you use a WASM binary, you trust the compiler that built it.

**I removed all three trusts.**

- **No compiler trust** — the WAT is generated by XSLT, not compiled. You can read the XSLT. You can verify the transform.
- **No binary trust** — the WAT is text. You can read every instruction. No opaque `.wasm` blob.
- **No runtime trust** — the WAT runs in any standard WASM runtime. No custom host functions. No hidden imports.

### Because XML is forever.

Rust changes. Cargo changes. Toolchains break. XML from 1998 still parses.

The DAG DSL is XML. The schema is XSD. The transform is XSLT 1.0 — a standard from 1999. This pipeline will work in 2050 the same way it works today.

### Because Hugging Face deserves better than black boxes.

HF Spaces run JavaScript. JavaScript runs WASM. WASM from this repo is *readable*. You can open the WAT file, read the inference engine, and know exactly what it does before you run it.

**No more "trust me, it runs." Read it yourself.**

## What Can It Do?

### Load any Hugging Face model

```javascript
// Parse a .safetensors header in the browser
const { instance } = await WebAssembly.instantiateStreaming(
  fetch('wat/safetensors.wasm')
);
const headerLen = instance.exports.parse_header_len(modelBytes);
const numel = instance.exports.tensor_numel(shapePtr, rank);
```

### Quantize weights

```javascript
// Q4_0: 32 weights → 18 bytes. Q8_0: 32 weights → 34 bytes.
const dequantized = instance.exports.dequant_q4_0_block(blockPtr, outPtr);
```

### Tokenize text

```javascript
// BPE, Unigram, WordPiece — all in WASM
const tokens = instance.exports.bpe_encode(textPtr, textLen, outPtr, capacity);
```

### Run inference

```javascript
// Full transformer forward pass — RMSNorm, RoPE, GQA attention, SwiGLU
const logits = instance.exports.forward(
  tokensPtr, nTokens, weightsPtr, kvCachePtr, logitsPtr,
  nLayers, hidden, vocab
);
```

### Verify provenance

```javascript
// BLAKE3 content-addressed hashing — every tensor verified
const kappa = instance.exports.kappa_of(dataPtr, dataLen, outPtr);
// "blake3:..." — the hash IS the address
```

## The Modules

| Module | What It Does | Why It Matters |
|---|---|---|
| **`sha256`** | FIPS 180-4 SHA-256, 64-round compression | The foundation. Every hash in the system. |
| **`kappahasher`** | BLAKE3 streaming hasher, kappa labels | Content-addressed archives. The hash *is* the address. |
| **`quant`** | Q4_0 / Q8_0 dequant, int8 encode | Shrink models 4-8×. Run big models on small machines. |
| **`safetensors`** | Header parse, dtype map, family registry | Load *any* HF model. Llama, Qwen, Mistral, Phi3. |
| **`tokenizer`** | BPE, Unigram, WordPiece | Tokenize text in the browser. No server. |
| **`regex`** | GPT-2 pre-tokenizer | The split that makes BPE work. Look-ahead failure modeled. |
| **`common`** | IR: DType, ops, matmul, softmax, norms | The typed intermediate representation. |
| **`inference`** | RMSNorm, RoPE, GQA attention, SwiGLU, forward | **The transformer.** The whole forward pass in WAT. |
| **`archive`** | .holo format, ledger | Content-addressed archives with append-only provenance. |

**9 modules. 65 functions. 1,361 lines of XML → 719 lines of WAT. All valid WASM.**

## The XML DAG DSL

Every computation is a DAG. Nodes are instructions. Edges are data flow.

```xml
<dag:module xmlns:dag="http://hologram.dev/dag" name="example">
  <dag:memory pages="1"/>
  <dag:function name="add_two" export="true">
    <dag:param name="a" type="i32"/>
    <dag:param name="b" type="i32"/>
    <dag:result type="i32"/>
    <dag:body>
      <dag:add type="i32">
        <dag:local.get name="a"/>
        <dag:local.get name="b"/>
      </dag:add>
    </dag:body>
  </dag:function>
</dag:module>
```

Becomes:

```wat
(module
  (memory 1)
  (func $add_two (export "add_two")
    (param $a i32)
    (param $b i32)
    (result i32)
    local.get $a
    local.get $b
    i32.add
  )
)
```

**You can read the XML. You can read the WAT. They say the same thing.**

## Hugging Face

This repo is built for Hugging Face.

### Spaces

Drop the `wat/` files into a Space. Load with `WebAssembly.instantiateStreaming`. Run inference in the browser. No Python. No GPU. No server.

### Models

The `safetensors` module parses `.safetensors` headers in WASM. Load any HF model, extract tensors, run in the browser. The `quant` module dequantizes Q4_0/Q8_0 weights — run quantized models client-side.

### Datasets

The `tokenizer` module encodes text to token IDs in WASM. Tokenize datasets client-side, no server round-trip.

### Provenance

The `kappahasher` module computes BLAKE3 hashes. Every tensor is content-addressed. Verify a model's integrity by checking its kappa against the manifest. No trust required.

## The Principle

```
CONSTRAINTS -> REPRESENTATION -> TRANSFORMATION -> EXECUTION -> VERIFICATION -> PROVENANCE
```

1. **Constraints** — What must be true? (The license, the schema, the types)
2. **Representation** — How do we express it? (XML DAG DSL)
3. **Transformation** — How do we convert it? (XSLT, deterministic)
4. **Execution** — How does it run? (WAT → WASM → browser)
5. **Verification** — How do we know it's correct? (WAT compiles, tests pass)
6. **Provenance** — How do we prove it? (BLAKE3 hashes, content-addressed)

Every step is visible. Every step is auditable. Every step is yours to inspect.

## Contributing

1. Write XML in `dsl/` following `dag.xsd`
2. Run `python3 tools/transform.py dsl/ wat/`
3. Verify: `python3 tools/validate.py`
4. **Never edit `wat/` directly** — it is generated

The XSLT is the contract. If your XML is valid, your WAT is valid.
